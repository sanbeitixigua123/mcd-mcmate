## 2. 为什么这样分层

### 编排层（SKILL.md）—— 负责"理解与解释"
模型擅长理解意图、处理模糊表达、组织语言。这一层不硬编码价格与营养，只规定**流程与边界**。

### 决策层（optimizer.py）—— 负责"算准"
点餐的核心决策是**组合优化**问题，模型直接"心算"容易出错且不可复现。把它下沉成算法后：

- 同样的输入 → 同样的输出（可复现、可解释、可测试）。
- 券的互斥与叠加规则被显式建模，不会"想当然地叠加"。
- 配餐在约束内做搜索，而不是拍脑袋。

### 接入层（mcd_client.py）—— 负责"连通"
把 MCP 协议细节（握手、SSE、错误码、写操作保护）封装起来，使：
- 命令行 / CI 可以脱离 MCP 客户端独立验证。
- 写操作有**白名单保护**，默认拒绝，避免误触下单/抽奖。

## 3. 券后最优价引擎

**问题**：给定购物车与一批券，找出实付最低的券组合。

**建模**：
- 券类型：`full_reduce`（满减）/ `discount`（折扣）/ `item_price`（单品特价）。
- 互斥：`group` 相同的券最多选一张；`group=None` 的券可自由叠加。
- 叠加上限：`max_stack` 限制同时使用的券数。

**算法**：按分组生成候选子集（每组"空 / 选一张"的笛卡尔积 × 自由券的幂集），逐个试算，取最小实付。

**套用顺序**（固定，保证确定性）：单品特价 → 折扣 → 满减。

```
输入：cart=[巨无霸×2], coupons=[满30减6(A), 9折(A), 满20减3(A)]
分组 A 候选：{空, 满30减6, 9折, 满20减3}
试算：51.0 → 45.0 → 45.9 → 48.0
输出：payable=45.0, saved=6.0, used=[满30减6]
```

## 4. 热量预算配餐引擎

**问题**：在热量上限内，选"主餐 + 小食(1~2) + 饮品"的最优组合。

**算法**：对候选空间做全枚举（`itertools.product`），对每个组合计算热量缺口与营养指标，按策略打分排序，返回 Top-K。

**策略**：

| 策略 | 打分侧重 |
| --- | --- |
| `balanced` | 热量贴合预算 + 蛋白质达标 + 钠约束 |
| `protein` | 蛋白质最大化，并对不达标组合加罚 |
| `low_sodium` | 钠最小化，超限重罚 |
| `cheapest` | 价格最小化（热量仍需达标） |

**约束**：组合热量不得超过 `budget × (1 + tolerance)`，默认 tolerance = 15%。

## 5. 数据流

```
MCP 工具返回（真实数据）
      │
      ├─→ list-nutrition-foods ──→ 营养库 ──┐
      ├─→ query-meals ───────────→ 在售菜单 ─┤
      │                                     ├─→ optimizer 复算 ─→ 方案
      └─→ query-store-coupons ───→ 可用券 ──┘
                                              │
      calculate-price（实算）←─────────────────┘
              │
              ▼
      最终报价（以实算为准）→ create-order → 官方支付链接
```

**关键约定**：`optimizer.py` 的输出是**决策建议**，最终报价一律以 `calculate-price` 的实算结果为准。两者不一致时，以 MCP 实算为准，并用它校准本地菜单数据。

## 6. 安全设计

| 机制 | 位置 | 作用 |
| --- | --- | --- |
| 写操作白名单 | `mcd_client.py: WRITE_TOOLS` | 默认拒绝下单/领券/抽奖/兑换，需显式放行 |
| Token 环境变量化 | `mcd_client.py: from_env` | Token 不落盘、不进代码 |
| 二次确认规则 | `SKILL.md` | 写操作前复述明细并取得同意 |
| 支付隔离 | `SKILL.md` | 只生成待支付订单，不接触支付 |
| `.gitignore` | 仓库根 | 阻止凭证误提交 |

## 7. 扩展点

- **新增券类型**（如买赠）：在 `optimizer._price_with_coupons` 增加一个分支即可。
- **新增配餐策略**：在 `plan_calorie_budget` 的 `strategy` 分支加一条打分规则。
- **接入其他 MCP 客户端**：`SKILL.md` 与工具名解耦于框架，直接复用。
- **离线回归**：`optimizer.py --selftest` 已可作为 CI 的回归用例。
